Architecture

Web Civics Databox architecture.

Digital information is defined legally as Intellectual Property. A Databox translates this principle into software architecture via a relationship-specific Solid exchange point — one organisation program × one person × one opaque box. The Mapping Smithy is the Web Civics control plane; deposits, receipts, and cryptographic evidence protect the shared rights of both parties.

Control plane — Mapping Smithy

Registers Institution Profiles, forges opaque relationship mappings, issues holder-bound connection credentials, and bridges source-system events into Databox deposits.

  • JSON API at /.databox/smithy
  • Authenticated with a control token (≥ 32 bytes)
  • Never uses an ordinary consumer token
  • Keeps raw customer IDs out of data-plane URLs and responses

Data plane — Solid resources

Authorised Solid HTTP/LDP operations for deposits, submissions, receipts and evidence. The Databox resource layout, composed authorizer and store integration are Web Civics extensions attached to the retained Solid request path.

  • Opaque box roots under /boxes/{opaque-box-id}/
  • Notify-then-pull delivery to the person’s chosen storage
  • Knowing a URL never grants access
  • Fail-closed when identity, policy, proof or evidence cannot be verified

Resource layout

Opaque boxes, independent identifiers.

Each Databox root is an opaque box. Identifiers are independently random so volume cannot be inferred by incrementing a sequence, and never contain customer data.

Security invariants

Rules that every implementation must hold.

One program, one relationship

A Databox belongs to one declared organisation program and one represented relationship.

No identifying paths

URLs, logs and storage paths must not contain directly identifying customer information.

URL ≠ authority

Knowing a resource URL never grants access.

No Pod browsing

Organisation credentials cannot authorise browsing of a consumer’s independent Pod.

Two-copy shared rights (ADR-0017)

In bilateral events (sales, dockets), rights are shared. Dual identical copies are deposited into both independent storage locations under separate WAC controllers, bound associatively by exact-byte SHA-256 digests.

Rights ontology governance (ODRL)

Data access and retention are governed by machine-computable W3C ODRL policies defining explicit permissions, duties, prohibitions, and moral provenance.

Explicit submissions

Consumer submissions are deliberate disclosures, not background reads from personal storage.

No silent overwrite

Accepted records are supersede-/tombstone-linked; changes remain auditable.

Assurance-gated sensitivity

Record sensitivity is evaluated against current verified assurance, purpose and policy.

Solid interoperability

The implementation preserves standard Solid HTTP behaviour for compatible agents.

Production Hardening & Enterprise Deployment

The Web Civics Databox enforces fail-closed security invariants across all execution paths. While the default single-process developer preset runs with lightweight in-memory and file stores for instant local evaluation, production enterprise and municipal deployments should configure durable SQL or Oxigraph storage backends, external Key Management Services (KMS), write-once-read-many (WORM) audit ledgers, and centralized identity provider integrations.
